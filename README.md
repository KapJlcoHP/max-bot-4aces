# МедМаршрут — бот + мини-приложение для платформы MAX

Хакатон MAX, команда **4Aces**, кейс «Забота о людях».

**Назначение.** МедМаршрут — цифровой помощник пациента с длительным лечением.
Врач назначил — пациент за 30 секунд зафиксировал назначения в маршруте; дальше
продукт сам ведёт по маршруту: напоминает о шагах, визитах, измерениях и приёме
лекарств, собирает дневники здоровья и формирует «Сводку для врача» в PDF
(только факты за 30 дней — без диагнозов и оценок «норма/не норма»).

## Основной пользовательский сценарий

1. В мессенджере MAX найдите бота по нику **@t24_hakaton_max_bot** (поиск по
   имени пользователя) и нажмите «Начать» / отправьте `/start` →
   кнопка «Открыть МедМаршрут» запускает мини-приложение (вход по подписанному
   `initData` из MAX, без регистрации).
2. Онбординг: регион, часовой пояс, согласие на обработку данных (152-ФЗ) —
   блокирующий шаг.
3. Маршрут: шаблон из каталога («Наблюдаться по хроническому», «Диспансеризация»,
   «Реабилитация», чекап и др. — 9 шаблонов) или свой маршрут в конструкторе.
4. «Врач назначил — записал»: назначения врача добавляются шагами маршрута со
   сроками.
5. Ведение: отметка шагов, курсы лекарств с отметкой приёма, дневники здоровья
   (давление, вес, сахар, самочувствие со шкалой боли).
6. Бот напоминает о шагах и визитах за день и за час, о приёмах лекарств и
   дневниках — по расписанию пользователя; `/svodka` присылает сводку PDF в чат.
7. На приёме пациент показывает «Сводку для врача» (PDF или экран).

## Состав и архитектура

```
zabota/
├── core/          # ядро: config, модели SQLAlchemy, сид справочников, демо-данные, pydantic-схемы
│   └── db/        # seed (справочники из content/*.json), demo (команда /demo)
├── bot/           # чат-бот (maxapi, long polling): команды, напоминания (scheduler), PDF в чат
├── server/        # FastAPI: REST /api/v1 (+ раздаёт собранный мини-ап и /docs)
├── web/           # мини-приложение: React 19 + TypeScript + MAX UI (@maxhub/max-ui)
├── content/       # контент вне кода: catalog.json, scenarios.json, regions.json, шрифты PDF
├── deploy/        # Caddyfile для prod-профиля
├── tests/         # автотесты (pytest): авторизация, маршрут, планировщик, тест-токен
├── DATA-API.yaml  # конфигурация обязательных проверок API (формат кейса)
├── TEST-DATA.json # тестовые данные и порядок проверки API
├── openapi.json   # OpenAPI 3.1 (генерируется scripts/export_openapi.py)
├── Dockerfile, compose.yaml, requirements.txt, .env.example
```

- **API:** FastAPI + SQLAlchemy 2.0 + SQLite, pydantic v2 (см. `requirements.txt`)
- **Бот:** [maxapi](https://love-apples.github.io/maxapi/) (long polling), анти-фlood, рестарт-цикл с backoff
- **Мини-ап:** Vite + React 19, MAX Bridge (`window.WebApp`), MAX UI; прод-сборка `web/dist` раздаётся API
- **Аутентификация:** подписанный `initData` (HMAC-SHA256) в заголовке `X-Max-Init-Data`,
  срок жизни 24 ч; для машинной проверки API — заголовок `X-Test-Token` (см. ниже)

## Запуск одной командой (Docker)

```bash
docker compose up -d --build
```

→ API и мини-приложение: **http://localhost:8000** (OpenAPI: http://localhost:8000/openapi.json, `/docs`).

Чат-бот (нужен `MAX_BOT_TOKEN` в `.env`; **экземпляр должен быть ровно один** — long polling):

```bash
docker compose --profile bot up -d --build
```

Прод с HTTPS (VPS + домен, см. `MEDROUTE_DOMAIN`):

```bash
docker compose --profile prod --profile bot up -d --build
```

Без Docker (dev, 3 процесса): `run_api.bat` (API :8000), `run_web.bat` (Vite :5173),
`run.bat` (бот).

## Переменные окружения

Заполняются в `.env` (образец без секретов — `.env.example`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `MAX_BOT_TOKEN` | токен бота MAX (обязателен для бота и проверки подписи initData) | — |
| `DATABASE_URL` | DSN базы; SQLite-файл в смонтированном `database/` | `sqlite:///./database/app.db` |
| `MINIAPP_PUBLIC_URL` | публичный https-адрес мини-апа (подсказки бота) | — |
| `MEDROUTE_DOMAIN` | домен для Caddy в prod-профиле | `localhost` |
| `DEV_BYPASS_AUTH` | только локально: вход без initData под демо-пользователем | `false` |
| `TEST_API_TOKEN` | токен тестового доступа к API для платформы (пусто = выключен) | — |
| `ALLOWED_ORIGINS` | CORS для dev-сервера Vite | `http://localhost:5173,...` |
| `TZ` | часовой пояс контейнеров (настраивается в compose) | `Europe/Moscow` |

**Порты:** приложение — `8000` (публикуется на `127.0.0.1:8000`); Caddy (prod) — `80/443`;
Vite (dev) — `5173`.

**Зависимости:** Python — `requirements.txt` (fastapi, uvicorn, sqlalchemy, pydantic,
pydantic-settings, maxapi, python-dotenv, reportlab, tzdata); мини-ап — `web/package.json`
(React 19, @maxhub/max-ui 0.5, vite). Автотесты: `pytest` (`pip install pytest`, `pytest tests/`).

**Внешние сервисы и интеграции:**
- MAX Bot API (`platform-api2.max.ru`) — бот, initData, диплинки `startapp`;
  для работы бота нужен доступ в интернет. Это единственный внешний сервис,
  без которого невозможно воспроизвести проверку основного сценария
  (мини-приложение обязано запускаться внутри MAX).
- Яндекс.Карты — только внешние ссылки «показать путь» из карточки организации.

## Работа с данными

- SQLite (`database/app.db`): пользователи, маршруты, шаги, дневники здоровья,
  курсы лекарств и отметки приёма, напоминания, журнал уведомлений.
- До согласия подписанный профиль MAX используется только для ответа на запрос:
  `GET /me` показывает временный профиль без записи в БД. `POST /me/consent`
  создаёт аккаунт и сохраняет регион, часовой пояс и дневники одной транзакцией.
- Справочники (регионы, организации, шаблоны маршрутов) — вне кода, в
  `content/*.json`; синхронизируются при каждом старте: добавить организацию =
  правка JSON без кода.
- 152-ФЗ: согласие — блокирующий экран онбординга; «Удалить мои данные» в
  профиле стирает аккаунт целиком (DELETE `/api/v1/me/data`); пароля нет —
  вход по подписанному initData из MAX.
- Показатели в интерфейсе и PDF — только факты; интерпретация («норма» и т.п.)
  отсутствует сознательно, оценка — работа врача.

## Тестовые данные и проверка

**Тестовый доступ к API** (для автоматической проверки платформой):
- `DATA-API.yaml` — перечень обязательных проверок (методы, параметры, роли,
  ожидаемые статус-коды и форматы ответа);
- `TEST-DATA.json` — тестовая учётная запись, тестовые данные, порядок проверки;
- доступ включается переменной `TEST_API_TOKEN` (сгенерировать:
  `python -c "import secrets; print(secrets.token_urlsafe(32))"`), запросы с
  заголовком `X-Test-Token` работают с тестовым профилем (MAX ID 909001);
  запись в БД создаётся при `POST /me/consent`;
- `openapi.json` — полное машинное описание API (OpenAPI 3.1), интерактивно — `/docs`.

Локальный смоук API на отдельной SQLite-БД: установить зависимости из
`requirements-smoke.txt`, затем запустить `python scripts/smoke_api.py` из корня проекта.

**Демо-данные в боте** — для живого показа без ручного ввода:
- `/demo` — наполняет аккаунт модельными данными: маршрут «Наблюдение по
  хроническому» (3 шага выполнены), 30 дней дневников (давление, вес, сахар,
  самочувствие), курсы лекарств с отметками приёма, два будущих визита;
- `/wipe` — очищает маршрут, дневники и лекарства (аккаунт и согласие остаются).

Новые аккаунты создаются **пустыми** — автосида нет. Все демо-данные
синтетические; названия и адреса организаций реальны (сверены с официальными
сайтами, перечень источников — `content/SOURCES.md`).

## Пошаговый сценарий проверки

1. В MAX найдите **@t24_hakaton_max_bot** → `/start` → «Открыть МедМаршрут».
2. Онбординг: выбрать регион, часовой пояс → согласие.
   *Ожидаемо:* главный экран с пустым маршрутом. Для показа модельных данных
   после согласия отправьте боту `/demo` и обновите мини-приложение.
3. «Маршрут» → «Новый маршрут» → шаблон «Наблюдаться по хроническому».
   *Ожидаемо:* таймлайн из 6 шагов, первый — текущий.
4. Открыть шаг → «Я это сделал». *Ожидаемо:* шаг выполнен, следующим становится
   следующий; кнопкой «Отменить выполнение» шаг возвращается.
5. «Дневники» → давление → 124/82, пульс 71. *Ожидаемо:* график и история обновились.
6. «Лекарства» → добавить курс «Эналаприл 10 мг» 08:00/20:00 → отметить приём.
7. «Сводка для врача» → PDF с агрегатами за 30 дней; кнопка «в чат» — тот же PDF
   присылает бот (или команда `/svodka`).
8. Профиль → «Удалить мои данные». *Ожидаемо:* аккаунт удалён целиком; следующий
   вход начинается с онбординга.
9. Машинная проверка API — по `DATA-API.yaml` с заголовком `X-Test-Token`;
   проверка завершается `DELETE /me/data` (сброс учётной записи).

## Известные ограничения

- Нет интеграции с МИС/ЕГИСЗ: назначения вносятся пользователем вручную
  (архитектура допускает замену источника данных).
- Телефоны и режимы организаций — справочные из открытых источников.
- Записи к врачу (слоты) в продукте нет: визиты и напоминания вносит пользователь; телефоны и режимы организаций - справочные, интеграций с гос-ИС нет (архитектура допускает замену источника данных).
- LLM не используется: сценарии и тексты детерминированные.
- Бот: один экземпляр на токен (long polling); напоминания приходят при
  запущенном контейнере `bot`.

## Остановка и повторный запуск

```bash
docker compose down            # остановить (данные в ./database сохраняются)
docker compose up -d --build   # запустить заново (справочники синхронизируются при старте)
```

Полный сброс данных: `docker compose down && rm -rf database/*` (удалит БД всех
пользователей).
